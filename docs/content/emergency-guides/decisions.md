# 응급 가이드 v1 결정·검토 요청

2026-09-15. 사용자 승인은 개발 구현 범위이며 의료 원고·이용허락·공개 배포 승인이 아니다.

## 구현·패키징

- 두 일반 랜딩 메뉴 → 주제 목록 → 주제별 공개 상태/출처 상세. 현재 공개 승인 본문 0건을 명시한다. 공통 기능 완료와 가이드 전체 완료를 구분한다.
- 일반 앱 ‘메뉴 → 앱 정보 → 개발 검수 · 응급 가이드 원고’ → 두 검토 목록 → 7개 실제 부분 원고. `kDebugMode && appFlavor == dev`에만 열리는 `/development/guides`이다. 런타임 모드 전환/저장 플래그는 없고 일반 경로는 항상 공개 repository 읽기다.
- 공개와 검수는 같은 GuideIndexPage/GuideDetailPage/본문 위젯을 사용한다. 검수 배너와 미해결 문장 목록은 검수 경로에만 표시한다. 가이드 전용 신규 Preview 앱을 만들지 않는다.
- 권리가 확인된 S03~S06/S12의 일부 텍스트를 재구성했다. 7개는 **미완성 부분 원고**이며 완료된 의료 매뉴얼이 아니다. 미해결 조건은 각 원고의 마지막 절에 담당 전문 분야·문장·근거 위치로 기록했다.
- 앱 자산에는 공식 PDF·알고리즘·의료 도해·제3자 사진을 넣지 않는다. 중립 fixture는 테스트 코드에만 존재한다. 실제 원고는 dev flavor 자산에만 있다. production에는 공개 메타데이터와 승인 manifest(현재 빈 목록)만 남긴다.
- 현재 production 배포 승인 없음. production APK는 미설치 패키징 검사 산출물일 뿐이다. `verify_emergency_guides.py`는 실제 ZIP 항목·내용·Dart payload의 원고 문자열을 검사한다. 검사는 승인 상태를 바꾸지 않는다.
- 승인 해시는 본문뿐 아니라 제목·대상·원본 버전 참조·권리·미해결 조건을 포함하는 전체 원고(Review 메타데이터 제외)에 연결한다. 공백 없는 UTF-8 JSON의 원래 key 순서를 유지한다. 문안/대상/버전 변경은 해시를 무효화한다.
- 일반 가이드는 ERouteScaffold/ERouteCard/공통 테마를 재사용한다. MemberScaffold/MemberSecurityScope를 사용하면 건강정보 조회가 시작되므로 사용하지 않는다. 기존 회원 보호를 해제하지 않는다.
- 119는 기존 coordinator와 공통 busy state. QA는 기본 Mock만 사용. 원문 링크는 별도의 HTTPS 호스트 allowlist와 명시적 탭, 실패 시 로컬 본문 유지. 스킴을 원고에서 실행하지 않는다.

## 누가 무엇을 확인해야 하는가

1. 소방청 119구급과 또는 신고 안내 담당자: S12 기반 신고/위치/기다리기 문안의 현재 절차 적합성, 신고 지연 방지, 연락처·인계 정보, 통화 종료/위치 정정 조건. S01/S02의 재사용가 필요한 부분은 해당 권리 담당자에게 별도 확인.
2. 소생술 전문 의료 검토자: CPR 시작·종료, 정상/비정상 호흡, 인공호흡 역량/의지, 연령과 체격, 미지원 특수 상황, AED 기기 차이/재분석/재개/인계 문구. 원문 도해를 시각적으로 확인한 사실이 의료 전문가의 검토를 뜻하지 않음.
3. 외상/응급처치 검토자: 지혈의 직접 압박 범위, 골절·관통상·박힌 물체, 심한 출혈, 거상·지혈대·전환 기준의 최신 근거. 이번 원고는 누락을 일반화하지 않음.
4. 화상/응급처치 검토자: 열화상 범위, 냉각 시간·온도·대상별 주의, 넓은/깊은 손상·저체온 위험, 의복 제거와 진료 전환 기준. 시간/온도는 원문에 없는 값을 생성하지 않음.
5. 권리 검토자: 제4유형 보완 표현·도해의 별도 허락 또는 독립적으로 재사용 가능한 대체 자료 검토. 제1유형으로 해결된 기존 부분 원고의 권리를 재차 허락 대기로 바꾸지 않음.
6. 제품 배포 책임자: 의료 검토와 이용조건을 충족한 **특정 원고 해시**의 공개 배포 승인. 사용자의 개발 Plan 승인이나 자동 테스트 결과로 대체하지 않음.

### 미발송 문의 문안

ERoute 모바일 앱에 해당 자료를 한국어 안내로 제공하려 합니다. 향후 상업적 이용 가능성이 있고 첫 실행 오프라인 열람을 위한 번들 포함과 가독성을 위한 문장 재구성이 필요합니다. S01/S02 중 신고 전달사항·동행인 길 안내·도착 시 인계정보의 사용 가능 범위, 제3자 권리 요소, 변경/상업적 이용 조건과 출처 표기, 최신 대체 자료를 알려주시기 바랍니다.

이 문의는 작성만 했으며 발송/답변/허락 수령하지 않았다.


## v1.1 결정 (2026-09-16 UTC)

- 사용자 승인 범위는 기존 일반 앱의 썸네일 7개·읽기 배치·원고 보류 정리·검증이다. UI 승인으로 의료/공개 승인 기록을 만들지 않는다. 공개 건수는 기존 승인 기록과 해시 검사로 결정한다.
- 이전 매트릭스의 모든 항목 ‘종료 절 필수’는 신고/위치의 정보 전달 범위에 적용하지 않는다. 두 ID의 `ending=[]`를 허용하고 빈 절은 표시하지 않는다. 실제 위험/정보 정정 검토는 유지한다. 다른 5개 항목의 조건을 완화하지 않는다. 의료 승인 정책 변경은 없음; 비임상 승인 담당 체계 변경은 향후 제품 책임자의 별도 정책 결정 대상이다.
- `GuideEntry`의 summary/thumbnailAsset은 주제 식별용 공개 메타데이터다. summary에는 처치 지시가 없다. Article ID/route/Repository와 119 coordinator를 재사용한다. 목록 읽기 상태도 실제 승인 본문 해시 검증 결과를 사용하며 손상 항목은 별도로 표시한다.
- 검수 패널은 Material ExpansionTile을 사용한다. 펼침 상태는 위젯 로컬 상태이며 공개 manifest/권한과 무관하다. 고정 툴바와 본문 배너에 개발 검토본 표시를 유지한다.
- 썸네일은 새 생성 비절차적 래스터 7개이며 기관 이미지/의료 도해를 사용하지 않았다. 원본과 목록 파생본은 별도 기록한다. 이미지 제작/적용 검수는 의료 정확성이나 독점 권리 보장이 아니다.
- 최신 S07 정오표는 제4장 전문소생술 도표 수정으로 이번 일반인 7개 주제에 전문소생술을 추가할 근거가 아니다. 제4유형 원문·렌더링은 임시 조사 경로에만 보관하고 앱/공개 산출물에 복제하지 않는다.
- 외부 검토 전달 자료는 매트릭스 각 행 + 해당 버전 원고 + refinement-changes.json + source-register의 정확한 근거 위치로 구성한다. 위에 적힌 담당 분야별로 남은 질문에 답하도록 요청한다. 자동 발송/새 허락 수령 없음.
