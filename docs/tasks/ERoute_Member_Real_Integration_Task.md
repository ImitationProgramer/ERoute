# ERoute 회원 기능 2차 — 휴대폰 번호·비밀번호 인증과 승인 UI의 일반 앱 연결

## 0. 목표와 우선순위

승인된 `features/member_ui/`의 재사용 화면을 일반 ERoute 앱에 연결한다.
이번에는 preview를 더 꾸미는 것이 아니라, 실제 개발 Backend/PostgreSQL을 통해
가입 → 로그인 → 별도 건강정보 동의 → 응급정보·수동 복용약 관리 → 로그아웃을 완성한다.

확정 요구사항:
- 회원가입·로그인은 휴대폰 번호 + 비밀번호 방식이다.
- PASS 및 외부 본인확인은 이번 방식의 선행조건이 아니며, 도입 계획에서 제외한다.
- SMS를 임의로 추가하지 않는다. 외부 본인확인을 생략했다는 이유로 가짜 인증 성공값을 만들지 않는다.
- 내부 userId는 계정·건강정보 소유권의 기준으로 유지한다.
- UI Preview는 검수용으로 유지하되, 일반 앱에는 preview 데이터·가짜 성공·캡처 허용 구현을 연결하지 않는다.
- 이번 다음 독립 작업은 브랜드 런처 아이콘 및 플랫폼별 테마 적용이다. 이번 인증 작업에 섞지 않는다.

계획은 아래 범위로 짧게 작성한다. 사용자 승인 후 단계별 구현·검증을 진행한다.
실제 저장소 조사 없이 특정 클래스의 현재 동작이나 테스트 성공을 가정하지 않는다.

## 2. 휴대폰 번호·비밀번호 계정 계약

### 2.1 휴대폰 번호

- 전화번호는 사용자가 입력하는 로그인 식별자이며, 내부 PK는 UUID userId다.
- 허용 국가·형식·정규화 규칙을 정의하고 Flutter/Backend/DB에서 일관되게 적용한다.
- 같은 번호의 표기 차이로 중복 계정이 생기지 않도록 DB 고유 제약과 동시 가입 처리를 둔다.
- 번호 검색용 식별값과 필요 시 표시용 암호문은 기존 개인정보 보호 방식과 양립시킨다.
  새로운 키 관리 프레임워크를 만들지 말고 기존 환경·키 버전을 재사용 가능한 범위에서 활용한다.
- 신규 가입 요청은 이미 있는 계정의 비밀번호나 소유권을 변경하지 않는다.
- 전화번호를 입력했다는 사실로 번호 소유·실명·연령을 검증했다고 표시하지 않는다.
- phone/identity verification은 미검증임을 유지한다. 기존 verified_identity를 가짜로 채워 넣지 않는다.
- 번호 선점·번호 재할당·계정 복구 위험과 미지원 범위를 운영 점검 항목에 남긴다.
  이를 이유로 이번 개발 로그인 전체를 PASS 준비 중으로 다시 막지는 않는다.

### 2.2 비밀번호

- 검증된 라이브러리의 비밀번호 전용 해시를 사용한다. Argon2id를 우선 검토한다.
- 알고리즘·salt·work factor·해시 버전 관리 및 필요한 라이브러리 의존성을 확인한다.
- 평문, 복호화 가능한 암호화, 단순 SHA-256/HMAC만으로 비밀번호를 저장하지 않는다.
- 길이·허용 문자·입력 상한·알려진 취약 비밀번호 차단 정책을 명세로 정하고 양쪽에서 검증한다.
- 붙여넣기·비밀번호 관리자·표시/숨기기를 지원하며 비밀번호를 조용히 자르지 않는다.
- 비밀번호 확인값은 UI의 오입력 방지용이며 별도로 저장하지 않는다.
- 실패 이유로 가입 여부·역할 등을 불필요하게 노출하지 않는 오류 응답을 사용한다.
- 가입/로그인 제한은 NMC 호출 budget과 분리하고, 계정 식별값과 IP 등의 제한을 적용한다.
  무제한 비밀번호 해시 연산이나 로그인 공격을 허용하지 않는다.
- 운영 인증 통신은 HTTPS를 전제로 한다. 로컬 예외가 일반 운영 설정으로 전파되지 않게 한다.
- 비밀번호·토큰·원문 전화번호·건강정보를 로그/테스트 결과/분석 도구에 출력하지 않는다.

### 2.3 회원가입·복구

- 회원가입과 기존 회원 로그인을 분리한다. 잘못된 비밀번호로 신규 회원을 자동 생성하지 않는다.
- 가입 동의 문서 버전과 사용자 행위를 실제 DB에 남긴다. 건강정보 동의를 묶거나 선동의시키지 않는다.
- 만 14세 이상 정책의 입력·자기확인 방식을 제안하되, 자기확인을 검증된 연령으로 기록하지 않는다.
- 전화번호만으로 비밀번호 재설정, 다른 계정 연결, 의료정보 이전을 허용하지 않는다.
- 번호 변경·분실 복구는 이번 범위 밖임을 정확히 안내한다. 실제로 작동하지 않는 성공 흐름을 만들지 않는다.
- 클라이언트 입력으로 OPERATOR 등 역할을 지정할 수 없게 한다.

## 3. 기존 데이터와 세션 보존

- 계정·건강정보·동의·NMC 테이블을 초기화하거나 기존 migration을 수정하지 않는다.
- 필요한 스키마 변경만 다음 Flyway migration으로 추가한다.
- 기존 개발 identity 계정을 전화번호 문자열만으로 신규 계정과 합치지 않는다.
- 개발 A/B/운영자 계정에 비밀번호 자격을 부여해야 한다면 local/test 환경 표시를 검증하는
  명시적 bootstrap/migration 경로로만 처리하고 기존 userId·건강정보를 보존한다.
- 기존 개발 credential 또는 preview password를 실제 비밀번호로 자동 복사하지 않는다.
- 생성한 테스트 자격정보는 비공개 로컬 파일로 제공한다. 공통 관리자 비밀번호나 고정 토큰을 커밋하지 않는다.
- 동일 명령 재실행으로 기존 건강정보를 지우거나 자격을 무조건 재설정하지 않는다.
- 필요 시 기존 개발 로그인 endpoint는 격리된 테스트 도구로만 유지한다.
  일반 앱의 기본 흐름은 새 휴대폰 번호·비밀번호 방식이다.

세션은 이미 구현한 불투명 토큰·서버 검증 구조를 재사용한다.
- Access 5분, 일반 회원 미사용 7일/최대 30일 및 refresh rotation 규칙 유지.
- 로그인 성공은 서버 검증 후에만 발생하며 재인증도 비밀번호 경로를 사용한다.
- 정상 refresh는 sessionGeneration을 불필요하게 변경하지 않는다.
- 로그아웃 완료 후 해당 access/refresh를 모두 거부하고 다른 세션은 일반 로그아웃으로 폐기하지 않는다.
- 전체 로그아웃과 오프라인 로컬 로그아웃/미확인 서버 폐기를 구분한다.
- 개발 계정·세션·preview 데이터가 운영 서버에서 수용되지 않는 기존 경계를 유지한다.
- 기존 release 검증에서 PASS 필수 부분은 새 credential 방식에 맞게 바꾸되 개발 우회 차단은 유지한다.
- 개발 서버 검증과 운영 공개 승인을 구분한다. 실제 사용자 대상 배포는 자동 수행하지 않는다.

## 4. 일반 앱에 승인 UI 연결

- 일반 앱 com.eroute.eroute_mobile의 로그인·회원가입·내 정보·내 응급정보·편집·복용약·동의 관리
  라우트를 승인된 동일 features/member_ui 위젯으로 연결한다. 별도의 동일 화면 복사본을 만들지 않는다.
- 기존 본인확인 전용 AuthPage가 일반 로그인 진입점으로 계속 나오지 않게 한다.
- ‘본인확인 서비스 준비 중이라 가입·로그인 불가’와 PASS 의무 문구를 새 경로에서 제거한다.
- MemberUiRepository의 실제 구현을 기존 API 계약에 연결한다. 지원하지 않는 API를 추정 호출하지 않는다.
- 저장/가입/삭제 성공은 서버 응답 확인 후에만 표시한다. 네트워크 실패를 메모리 성공으로 대체하지 않는다.
- 로그인 후 원래 의도한 내부 회원 화면으로 복귀하고 Drawer/내 정보/보호 화면의 세션 상태를 동기화한다.
- 일반 앱에서는 preview banner·가상 데이터·검수 도구·캡처 예외 주입을 사용하지 않는다.
  개발 테스트 데이터 경고는 필요하다면 별도 development 표기로 정확히 유지한다.
- 로그아웃·계정 전환·동의 철회 시 관련 캐시/초안/요청을 제거하고 늦은 응답을 폐기한다.
- 기존 네이티브 화면 보호·복귀 재검증·메모리 초안 10분 규칙을 새 화면에 실제 연결한다.
  일반 앱 촬영을 위해 보호 장치를 끄지 않는다.
- 건강정보의 기기 영구 사본·자동 전송·가족 정보는 추가하지 않는다.

## 5. 항목 편집과 삭제의 데이터 계약

- 알레르기·기저질환·복용약은 UNSET/NONE/RECORDED 의미를 유지하고 메모는 선택 문자열로 둔다.
- 항목별 저장은 편집한 항목만 변경한다. 기존 전체 PUT 사용 시 편집 시작 당시
  baseVersion/consentEpoch의 전체 스냅샷을 보존하고 서버에서도 원자적으로 버전을 검사한다.
- 최신 GET에 오래된 초안을 합쳐 덮어쓰거나 변경하지 않은 항목을 빈 값으로 전송하지 않는다.
- API 변경이 필요하면 additive한 최소 변경과 실제 계약 테스트를 제시한다.
- 모든 소유권은 서버 principal에서 결정한다. 회원 B나 운영자에게 A의 건강정보 접근을 허용하지 않는다.
- 응급 기록 삭제는 알레르기·기저질환·메모 범위를, 약 삭제는 해당 약을,
  동의 철회는 모든 건강정보·약을 대상으로 한다. 각 동작과 계정 유지 여부를 구분한다.
- 철회는 세션 전체 로그아웃이 아니다. 세션은 유효해도 건강정보 접근은 차단한다.
- 재동의/지연 쓰기/다른 기기 요청이 삭제된 이전 데이터를 되살리지 않게 한다.
- 서비스 DB 삭제와 실제 백업 파기 완료를 구분하여 기존 상태와 증거 정책을 유지한다.

## 6. 식약처 미연동 상태의 복용약

현재 승인된 검색 UI의 가상 제품은 일반 앱의 실제 약품 데이터가 아니다.
- preview 검색·선택·확인 기능은 UI 검수용으로 계속 유지한다.
- 이번 일반 앱에서는 기존 Backend의 수동 복용약 CRUD를 실제 연결한다.
- 식약처 실제 검색 전에는 ‘약 검색 준비 중’과 ‘직접 입력’을 구분하고 실제 등록 가능한 경로를 제공한다.
- UI capability를 명시적으로 처리한다. 네트워크 실패 시 가상 검색 결과로 fallback하지 않는다.
- preview-product-* 식별자나 UI_PREVIEW_PRODUCTS 출처를 실제 개인 복용약으로 저장하지 않는다.
- Backend도 검증되지 않은 제품 연결과 임의의 MFDS 출처를 수용하지 않는다.
- 수동 기록은 제품코드 미연결 상태로 두고, 향후 실제 제품 선택 후 사용자 확인으로 연결한다.
- 이번에 식약처 API/낱알식별/DUR/복약 권고/전수 수집을 추가하지 않는다.
- ‘약 검색 UI 완료’, ‘수동 복용약 실제 저장 완료’, ‘식약처 실제 연동 미완료’를 별도 보고한다.

## 7. 지도·실행환경 회귀 방지

첨부 최신 README에는 이전 일반 dev APK에서 지도 Client ID와 Backend 주소가 빠져
지도/병원 조회가 막혔고, 당시 smoke 검증이 시작·로그인에 한정됐다는 정정이 있다.

- 기존 실행 스크립트의 지도 설정·API_BASE_URL·개발 환경 설정을 확인하고 유지한다.
- 필요한 값 없이 빌드한 앱의 실행 성공만으로 일반 앱 회귀 통과라고 보고하지 않는다.
- 명시적인 개발 DB/키/환경에서 회원 API와 기존 병원 조회 모두 동작하는지 확인한다.
  회원 DB 연결을 바꾸면서 병원 Master가 사라진 DB를 무심코 사용하지 않는다.
- API 키·전체 비밀 설정을 로그/채팅/보고서에 출력하지 않는다.
- 119 진입·병원 검색·상세는 비회원으로 유지하고 인증 장애도 이를 막지 않게 한다.
- NMC 필드 의미·지역 매핑·TTL·호출 예산/초당 제한은 변경하지 않는다.
- 회원 기능만 반복할 때 NMC 호출이 늘지 않는지 격리 조건에서 검증한다.
- 실제 지도 검색에 필요한 NMC 실측은 기존 guard 아래 최소 범위로 별도 집계한다.
- 시작 전 포트와 프로세스를 확인하고 기존 서비스의 소유권을 존중한다.
  새로 실행한 Backend/DB의 PID·포트·기동 상태와 종료 방법은 비밀 없이 보고한다.
- 기존 DB를 삭제하거나 에뮬레이터 데이터를 무조건 초기화하지 않는다.

## 8. 필수 완료 검증

가상 계정/가상 건강정보 + 실제 개발 Backend/DB로 검증한다.

1. 일반 ERoute 앱에서 신규 가입 → 로그인 → 서버 userId/세션 확인.
2. 잘못된 비밀번호/잘못된 번호 입력은 로그인 거부. 기존 회원을 새 계정으로 만들지 않음.
3. 표기 차이/동시 가입의 중복 번호 방지. 기존 계정 비밀번호·건강정보 변경 없음.
4. 가입 동의와 별도 건강정보 동의 확인, 동의 없이 건강정보 접근 차단.
5. 항목 저장/편집/약 수동 등록 → DB 반영 → 재조회/로그아웃·재로그인 후 같은 내용 확인.
6. A/B 소유권과 운영자 접근 제한, 계정 전환 직후 캐시·초안 노출 방지.
7. 단일 항목 보존, baseVersion/consentEpoch 충돌, 지연 응답, 중복 요청, 오류 상태 검증.
8. 기존 세션 만료/refresh/로그아웃/전체 로그아웃 테스트 유지.
9. 동의 철회 → 의료정보 삭제 및 접근 차단 → 계정/세션 유지 → 재동의 시 과거 기록 복원 없음.
10. preview 가짜 인증·제품·세션·캡처 허용 구현의 일반/production 유입 차단.
11. 최종 일반 APK의 비회원 지도 SDK 초기화·GPS 또는 수동 검색·병원 상세 확인.
12. 실제 전화/PASS/SMS launcher 호출 0. 자동 테스트는 외부 약품/NMC 호출 없이 실행.
13. iOS·실기기 미검증은 그대로 보고. Android 테스트 성공으로 대체하지 않음.

## 9. 산출물과 종료 기준

- 먼저 변경 API/스키마/계정 전환/일반 앱 연결/복용약 capability를 담은 짧은 Plan.
- 승인 후 실제 구현, migration·세션·권한·Flutter·HTTP 통합 테스트 결과.
- 일반 ERoute 앱의 실제 로그인·가입 흐름과 서버 저장 검증 증거.
- 실행한 Backend artifact 식별정보와 실제 설치 APK application ID/버전/해시/빌드 시각.
- finalization README의 과거 일반 dev APK 해시와 복구된 최신 APK 해시를 혼동하지 않음.
- 어떤 앱을 열어야 하는지, 가상 테스트 계정 자격정보를 로컬에서 확인할 방법.
- 키·비밀번호·토큰 원문은 문서/채팅에 출력하지 않음.
- 테스트 DB, 실행 프로세스·포트, 명시적 종료 방법과 미완료 항목.
- 이번 완료 뒤 아이콘 작업으로 자동 확장하지 않고 실제 회원 흐름 QA를 받는다.

## 10. 다음 독립 작업 — 아이콘 (이번에는 구현하지 않음)

회원 연동 완료 후 정식 ERoute 아이콘 자산과 UI Preview 식별용 변형을 적용한다.
기본 컬러 아이콘을 실제 런처에 먼저 적용하고, 기기 테마에 따른 표현은 플랫폼 지원에 맞게 검증한다.
Android의 테마 tint/단색 아이콘과 컬러 Day/Night 장면 교체를 같은 기능으로 가정하지 않는다.
아이콘 디자인 이미지의 존재만으로 APK 아이콘 리소스가 교체됐다고 보고하지 않는다.
