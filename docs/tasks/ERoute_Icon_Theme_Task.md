# ERoute 정식 아이콘·시스템 테마 대응 작업

작성일: 2026-09-15
상태: 다음 Codex 작업용 명세. 저장소 수정·아이콘 제작·빌드 완료를 뜻하지 않는다.

## 1. 확정한 주요 개발 순서

| 순서 | 작업 | 완료 범위 |
|---|---|---|
| 1 — 이번 작업 | 브랜드 아이콘·기기 테마 대응 | 아이콘 원본 확정, 일반/Preview 구분, 지원 플랫폼 리소스 연결과 홈 화면 검수 |
| 2 | 응급상황 대처요령·응급처치 가이드 | 역할이 다른 두 메뉴를 출처·검토일·이용 조건을 확인한 콘텐츠에 연결 |
| 3 | 기저질환 관련 진료과 표시 v1 | 사용자 확인 질환과 검토된 진료과 연결 규칙으로 기존 검색 결과를 추가 강조 |
| 4 | 식약처 약 검색 실제 연동 | 제품 허가정보·e약은요 검증 후 검색→제품 확인→회원 복용약 저장 연결 |
| 5 | HIRA 등 근거 보강 | 실제 필요한 전문의·특수진료 정보와 기관 식별자 대응을 검증하여 추가 |

- 길찾기·공유·즐겨찾기·중증질환 수용정보·가족 정보·119 실제 정보 전송은 별도 후속 목록으로 유지한다. 위 작업에 몰래 포함하지 않는다.
- 실기기/iOS, 계정 복구·번호 재할당 정책, 삭제·백업, NMC 원천 시간대·장시간 열린 화면의 최신성 검증은 공개 전 별도 통과 조건으로 유지한다.
- 기저질환 관련 진료과 표시 v1은 식약처·DUR·HIRA의 전체 완료를 선행조건으로 두지 않는다. 단, 실제 사용 가능한 진료과 데이터와 검토된 연결 규칙이 있어야 표시한다.
- v1은 ‘관련 진료과 정보’ 표시이며 실제 치료·당일 진료·응급 수용 가능 보장이 아니다. 노란 강조와 사용자의 수동 즐겨찾기는 별개다. 일반 검색 결과를 숨기거나 거리순을 바꾸지 않는다.
- 위 후속 기능은 이번에 구현하지 않는다.

## 2. 이번 작업의 목표와 중단선

기본 Flutter 런처 아이콘을 ERoute 브랜드 아이콘으로 교체한다. 앱 내부 테마와 홈 화면 아이콘 외형은 별개의 기능으로 검증한다.

한꺼번에 모든 디자인을 새로 만들지 않는다. 기존 아이콘 시안의 01 여정형(길·지평선 구도)을 우선 후보로 Light/Dark 한 쌍을 구체화한다. 이는 시각 방향이며, 최종 심벌·원본 이미지 자체의 승인 완료를 뜻하지 않는다.

진행은 두 단계다.
1. 기존 리소스·지원 환경 조사 → 아이콘 원본/축소 비교와 적용 계획 제시 → 사용자 시안 확인.
2. 승인된 원본만 플랫폼 리소스에 연결 → 기존 일반/Preview 앱을 업데이트 설치 → 실제 홈 화면 검수.

첫 Plan에는 두 단계를 포함하되, 미승인 이미지를 최종 브랜드 자산으로 확정하지 않는다. 최종 검수 후에는 다음 가이드 작업으로 자동 확장하지 않는다.

## 3. 시작 전에 확인할 것

- 현재 작업 트리·브랜치·미커밋 변경을 확인하고 기존 변경을 덮어쓰지 않는다.
- AGENTS.md, DESIGN.md, UX-CONTRACT.md와 최신 QA/실행 문서를 먼저 읽는다.
- Android manifest, flavor별 리소스, ic_launcher/roundIcon, 스플래시의 기존 아이콘 참조, iOS AppIcon/asset catalog, 현재 테마 모드와 사용자 설정을 조사한다.
- 현재 Flutter·Android SDK·Xcode/아이콘 도구·시뮬레이터·런처의 실제 버전을 기록한다. 과거의 설치·검증 상태를 현재 상태로 간주하지 않는다.
- 일반 앱 ID `com.eroute.eroute_mobile`, Preview ID `com.eroute.eroute_mobile.preview`와 앱 이름·배포/디버그 격리를 유지한다.
- docs/ui/references 등에서 실제 아이콘 시안 파일을 찾아 열고 경로·해시를 기록한다. 회원 UI 시안을 아이콘 시안으로 착각하지 않는다.
- 시안 파일이 없으면 필요한 정확한 파일 위치를 요청한다. 읽지 않은 이미지를 확인했다고 쓰거나 임의의 기존 자산 경로를 만들지 않는다.

## 4. 시각 디자인 및 자산

### 유지할 방향
- Light/Dark는 같은 길·목적지·실루엣을 사용하고 하늘·조명·색감만 변형한다.
- Light: 밝은 하늘과 따뜻한 지평선. Dark: 짙은 남색 하늘과 은은한 빛. 작은 크기에서도 길과 중심 심벌을 식별할 수 있게 단순화한다.
- 중심 심벌은 독자적인 E 또는 경로·목적지 심벌을 우선 제안하고 사용자에게 확인받는다. 기존 시안의 상징을 변경했다면 그 차이를 명시한다. 공식 119·공공기관·의료기관 로고를 복제하거나 제휴·공인을 암시하지 않는다.
- 아이콘 내부에 작은 ERoute 전체 이름·슬로건을 넣지 않는다. 시스템이 표시하는 앱 이름을 유지한다.
- 일반/Preview를 동일 아이콘으로 구분 불가능하게 만들지 않는다. Preview에는 안전 영역 안의 간결한 P 표시 또는 고유한 형태 차이를 둔다. 색 차이만으로 구분하지 않는다.

### 원본과 파생 파일
- 발표 이미지의 작은 칸을 잘라 확대해 최종 아이콘으로 쓰지 않는다.
- 편집 가능한 원본 또는 충분한 해상도의 원본, Light/Dark/단색 자산, 생성 방법·출처·버전·해시를 남긴다.
- 벡터 원본이 없으면 래스터를 SVG 파일로 감싼 것을 벡터 원본이라고 주장하지 않는다.
- Android 전경·배경·단색, 기존 지원 범위에 필요한 legacy/round 리소스와 iOS 지원 외형을 준비한다.
- OS 마스크가 적용되는 레이어에 휴대폰 테두리·바깥 그림자·완성된 둥근 모서리를 불필요하게 구워 넣지 않는다.
- 미리보기에는 Light/Dark 한 쌍, 일반/Preview 구분, 작은 크기, 원형·둥근 사각형 크롭, 단색 결과를 함께 제시한다. 시각 검수용 크기와 플랫폼 요구 크기를 구분한다.

## 5. 기기 테마 및 플랫폼 적용 원칙

### 앱 내부
- 기본 정책은 기기 설정 따르기다. 이미 구현되어 있으면 재사용하고, 기존 사용자 수동 테마 선택이 있으면 임의로 덮어쓰지 않는다.
- ThemeMode.system 및 기존 brightness 흐름을 확인한다. 앱 내부 로고를 사용한다면 그 테마에 맞는 자산을 표시한다.
- 기기 시간·일출/일몰을 직접 계산하지 않는다. 위치 권한, 새 일정 작업, 주기적인 서버 요청을 추가하지 않는다.
- 기존 랜딩·회원·병원 UI의 색상/레이아웃을 전면 재설계하지 않는다. 앱 내부 테마를 바꿨다고 런처 아이콘이 바뀌었다고 보고하지 않는다.

### Android
- 공식 adaptive icon의 전경·배경과 직접 만든 monochrome 레이어를 기본 지원으로 한다.
- 단색 테마 아이콘은 풍경 Light/Dark 이미지 교체와 다른 결과다. Android 버전·런처·사용자의 themed icons 설정별 동작을 기록한다.
- 플랫폼/런처가 풍경 자동 교체를 보장하지 않는 경우 기본 컬러 아이콘을 fallback으로 유지하고 한계를 보고한다.
- drawable-night 하나 또는 앱 종료/실행 때의 임의 alias 교체만으로 모든 런처에서 자동 전환된다고 주장하지 않는다.
- 첫 버전에는 정시 알람·서비스·반복 polling·강제 런처 재시작·activity-alias 전환 우회 구현을 넣지 않는다.
- 실제 SDK 버전에 맞는 공식 규격, 마스크 안전 영역, Android 13+ 단색 처리와 현재 Android의 자동 테마 처리 차이를 공식 문서로 확인한다.

### iOS
- 실제 설치된 Xcode와 배포 대상에 맞춰 기존 asset catalog의 외형별 자산 또는 Icon Composer를 선택한다. 도구 업그레이드는 필요한 근거와 영향을 제시한 뒤 별도로 결정한다.
- 사용자 홈 화면의 기본/다크/자동/틴트 등 설정을 존중한다. 앱 내부 ThemeMode만으로 아이콘 선택을 강제하지 않는다.
- 앱이 주기적으로 alternate icon을 교체하는 방식을 기본으로 채택하지 않는다.
- Xcode·시뮬레이터가 없으면 자산 준비/설정 검사와 실제 iOS 빌드·기기 검증을 구분한다. 미검증을 Android 성공으로 대체하지 않는다.

## 6. 이번에 바꾸지 않는 것

- Backend·DB migration·인증/계정 식별·세션 만료·건강정보 동의·암호화·삭제.
- 회원 UI 재개편, 식약처/HIRA API, 가이드 본문, 기저질환 매칭·지도 마커.
- NMC 필드 의미·TTL·원천 최신성·호출 가드·검색 반경.
- 실제 PASS·SMS·병원/119 전화 launcher 호출. 기존 mock 정책을 유지한다.
- 기존 네이티브 건강정보 화면 보호. 캡처는 홈 화면·앱 서랍·공개 화면에서 수행한다.
- 패키지 ID·기존 설치 데이터·로그인 상태·지도 Client ID·Backend 주소·키.

## 7. 검수와 종료 조건

- 승인된 브랜드가 기본 Flutter 아이콘을 대체했는지 홈 화면·앱 서랍·설정 목록·최근 앱/스플래시 등 기존 OS 사용 위치를 확인한다. 플랫폼별 차이는 기록한다.
- 일반/Preview 동시 설치와 각각 올바른 앱 실행을 확인한다. 운영 빌드에 Preview 배지나 가상 데이터가 유입되지 않아야 한다.
- 밝음/어두움, themed icons 켜짐/꺼짐, 앱 실행 중·종료 상태·재실행을 비교한다. 기기 설정을 바꾼 경우 종료 시 원래 값으로 복구한다.
- 핵심 심벌이 원형/둥근 사각형에서 잘리지 않고 작은 크기와 밝은/어두운 배경에서 식별되는지 확인한다.
- 아이콘 캐시 확인을 위해 기존 앱을 삭제하거나 앱/런처 데이터를 지우지 않는다. 먼저 업데이트 설치·공개 런처 화면 재확인으로 점검하고 캐시의 한계는 기록한다. 파괴적 작업은 별도 승인 없이는 하지 않는다.
- 일반 앱은 기존 설정 주입 실행 경로를 이용해 빌드·업데이트한다. 로그인/세션 복원·공개 화면·기존 지도 진입에 회귀가 없는지 확인한다.
- 아이콘/테마 테스트는 저장된 데이터나 fixture를 사용하여 NMC·식약처 실제 추가 호출을 유발하지 않는다. 예상 밖 호출이 있었다면 0이라고 보고하지 말고 이유와 횟수를 적는다.
- flutter analyze, 기존 Flutter 회귀, 리소스/flavor/운영 격리 검사와 가능한 Android 빌드를 실행한다. iOS는 준비·빌드·기기 검수 상태를 나눠 보고한다.

최종 보고에 포함할 사항:
- 원본/파생 파일 목록, 승인된 디자인, 생성·내보내기 방법.
- OS·런처·모양 설정별 지원표: 설계상 지원/실측 통과/미지원 fallback/미검증 구분.
- 홈 화면의 일반·Preview, Light/Dark/테마 아이콘 비교 캡처.
- 실제 application ID·버전·빌드 시각·APK 해시·설치본 일치, 실행/검증 명령.
- 원래 데이터/설정 유지 여부, 새로 시작·종료한 프로세스와 안전한 종료 방법. 자격정보·개인 건강정보는 출력하지 않는다.
