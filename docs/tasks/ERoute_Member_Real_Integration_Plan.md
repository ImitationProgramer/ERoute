# 회원 실제 연동 승인 계획

1. **인증 API:** 휴대폰 번호·비밀번호 가입/로그인/재인증을 구현한다. PASS 준비 상태·VERIFIED 결과에 의존하지 않는다. NFC 코드포인트 15~128, Argon2id, 버전별 취약 비밀번호 목록과 IP/식별자 제한을 적용한다. 번호 소유·실명·연령은 미검증으로 두고 나이는 자기확인만 기록한다.
2. **DB·기존 계정:** V9로 비밀번호 자격과 키 기반 번호 인덱스를 추가한다. 기존 userId·세션·건강정보·암호화·동의·삭제·병원 데이터를 보존한다. 기존 개발 계정은 명시적 local/test userId bootstrap으로만 자격을 부여하며 번호만으로 자동 병합하거나 자격을 재설정하지 않는다.
3. **라우터·저장 계약:** 승인된 동일 위젯을 일반 라우터와 실제 Repository에 연결한다. health-snapshot은 동의 행 잠금으로 프로필·복용약·version·consentEpoch의 일관성을 유지한다. 복용약 변경의 baseVersion·consentEpoch는 필수로 검증하며 수정/삭제는 약 version도 검증한다. 누락 400과 충돌 409를 구분하고 서버 최신값으로 보충하지 않는다. 구버전 앱 호환을 이유로 버전·동의 검사를 생략하지 않으며 OpenAPI·Flutter DTO·테스트를 함께 변경한다. 오래된 편집은 최신 데이터에 자동 병합하지 않는다. 약 검색은 준비 상태를 안내하고 수동 입력 CRUD를 실제 연결한다.
4. **접근권한·통합 테스트:** 일반 가입 화면에서 새 가상 계정을 만들고 실제 개발 Backend/DB로 별도 건강정보 동의·저장·재로그인·철회·로그아웃을 검증한다. A/B 소유권·운영자 차단, 동시 수정/철회 snapshot, 버전/epoch·지연 응답·세션·Unicode·Preview 격리를 테스트한다. 기존 데이터는 초기화하지 않는다.
5. **최종 일반 APK 검수:** com.eroute.eroute_mobile에서 회원 흐름과 같은 APK의 비회원 지도·병원 검색·상세·119 진입을 검수한다. 기존 지도 Client ID·Backend 주소·DB·키와 호출 가드를 유지한다. 회원 NMC 증가 0건, 지도 실측은 별도 집계한다. APK/Backend 식별정보·프로세스·종료 방법·미검증 플랫폼을 기록한다. 실제 PASS·SMS·전화 launcher, 식약처 실제 연동, 아이콘 및 공개 배포는 수행하지 않는다.
