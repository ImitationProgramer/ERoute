# ERoute 응급 가이드 v1 — 공식 자료 검토·오프라인 안내·일반 앱 연결

작성일: 2026-09-15
문서 성격: 다음 Codex 작업을 위한 제품·구현 명세 및 1차 출처 조사 기록
상태: 구현 요청용. 의료 본문 최종 승인, 이용허락 완료, 앱 구현 완료를 뜻하지 않는다.

## 1. 목표와 이번 종료선

일반 ERoute의 랜딩에 남아 있는 `응급상황 대처요령`과 `응급처치 가이드`를 실제 안내 화면으로 연결한다.

- 대처요령은 신고·위치 설명·구급차 도착 전 준비를 다룬다.
- 응급처치 가이드는 주제가 명확한 기본 안내를 찾아 읽는 기능이다. 진단·중증도 판정·개인별 의료 조언 도구가 아니다.
- 로그인·건강정보 동의·GPS·Backend 응답 없이 읽을 수 있게 한다.
- 채택한 본문은 앱 번들에 넣어 설치 후 첫 실행부터 오프라인으로 제공한다. 외부 링크·영상만으로 구현하지 않는다.
- 기존 디자인, 일반/Preview 아이콘, 회원 세션, 서버 데이터, 지도 설정과 119 안전 경계를 유지한다.
- 이번 단계의 완료는 `앱 기능 검증`과 `콘텐츠의 정확성·이용권한·공개 가능 여부`를 별도로 보고한다.
- 후속 순서는 가이드 → 기저질환 관련 진료과 표시 v1 → 식약처 약 검색 → HIRA 등 근거 보강이다. 이번에 후속 기능을 구현하지 않는다.

현재 저장소 코드는 이 문서를 실행하는 Codex가 먼저 조사해야 한다. 아래 경로·클래스명은 기존 구현에 맞춰 조정할 제안이며, 현재 존재한다고 가정하지 않는다.

## 2. 시작 전에 보존할 기준

다음 최신 기록부터 읽는다.

- `docs/qa/icon-theme-2026-09-15/README.md`
- `docs/qa/freshness-ui-2026-09-15/README.md`
- 현재 `DESIGN.md`, `UX-CONTRACT.md`, `AGENTS.md`, 일반 앱 실행 문서
- 현재 Landing/Router, 공개 기능 초기화, EmergencyDialer와 테스트 대체 주입, 앱 시작 시 인증 복원 경로

아이콘 검수 보고서에는 일반 빌드에서 인증 환경 기본값이 `disabled`로 들어갔다가 기존 `local` 설정으로 복구한 이력이 있다. 동일 실수를 반복하지 않는다.

- 일반 앱 ID는 기존 `com.eroute.eroute_mobile`을 유지한다.
- 기존 설정 주입 스크립트와 서명을 사용한다. 환경변수 값은 현재 로컬 파일에서 확인하며 채팅이나 QA 보고서에 비밀을 출력하지 않는다.
- `.env`, 지도 Client ID, Backend 주소, DB·키, 로그인 세션, 아이콘 리소스와 사용자 미추적 파일을 보존한다.
- 다른 작업에서 실행 중인 Backend·DB·에뮬레이터를 임의 종료하지 않는다.
- 앱 삭제, 앱/런처 데이터 초기화, DB reset으로 검증을 쉽게 만들지 않는다.
- 보고서의 과거 PID는 현재 프로세스라고 가정하지 않는다.

## 3. 1차 콘텐츠 범위: 7개 항목을 후보로 선정

아래는 콘텐츠 작성 범위다. 처치 본문 자체나 최종 공개 승인 목록이 아니다. 특정 항목의 근거·권리가 해결되지 않으면 그 항목만 보류하고 해결된 항목과 공통 UI 개발은 진행한다.

| 분류 | ID 제안 | 제목 | 다룰 범위 | 주의할 경계 |
|---|---|---|---|---|
| 대처요령 | report-119 | 119에 알려줄 내용 | 환자 발생, 위치, 상태, 알려진 병력·복용약, 연락 가능한 정보 전달 | 신고 전 입력·체크 완료를 요구하지 않음. 수집·자동 전송 없음 |
| 대처요령 | explain-location | 주소를 모를 때 위치 설명 | 공식 신고 안내에서 제시한 주변 식별 정보 | GPS 획득 성공을 선행조건으로 만들지 않음 |
| 대처요령 | before-ambulance | 구급차가 도착하기 전 | 신고 접수자의 안내, 여력이 있는 동행인의 안내·준비, 도착 시 전달 정보 | 준비물 챙기기 때문에 신고·처치를 늦추도록 표현하지 않음 |
| 응급처치 | adult-cpr | 성인 심폐소생술 | 원문에 따른 적용 대상·시작 조건·절차·중단/인계 조건 | 일반인 기준. 소아·영아·익수 등 별도 알고리즘과 섞지 않음 |
| 응급처치 | adult-aed | 성인 자동심장충격기(AED) | 해당 대상의 사용 절차·안전 주의와 기기 안내 | 성인 범위를 명시. AED 위치 검색 기능은 이번에 추가하지 않음 |
| 응급처치 | external-bleeding | 외부 출혈·상처 | 검증된 일반인 초기 대응 범위 | 지혈대·박힌 물체·골절 등 조건을 임의 생략하거나 일반화하지 않음 |
| 응급처치 | thermal-burn | 열에 의한 화상 | 확인된 대상·상황에서의 기본 안내 | 화학·전기 화상까지 같은 절차로 적용하지 않음 |

신고 안내의 이용 연령과 처치 콘텐츠의 적용 대상은 별개다. 회원가입의 만 14세 기준으로 CPR의 성인·소아 경계를 정하지 않는다. 대상 정의는 해당 의료 원문에 따라 기록한다.

기도폐쇄, 소아·영아 CPR, 익수, 경련, 흉통·뇌졸중 판단, 약물 사용, 재난별 대피 전반은 이번 범위에 임의 추가하지 않는다. 필요하면 후속 후보만 기록한다. 미지원 상황을 성인 일반 절차로 자동 대체하지 않는다.

### 4.3 정확성과 권리의 채택 기준

- 공공누리 제1유형이라는 사실은 의료 내용이 현재 상황·대상에 적합하다는 보장이 아니다. 2022 게시물을 2025판과 대조해야 한다.
- 최신 지침이라는 사실도 자유로운 상업적 복제·변형 허락을 뜻하지 않는다.
- 자료 간 불일치가 발견되면 어느 쪽을 왜 채택할지 근거·범위를 기록한다. 다른 지침의 일부만 섞어 새로운 처치 순서를 만들지 않는다.
- 각 처치의 적용 대상, 시작 조건, 주의/금지, 다음 단계·중단 조건과 숫자 단위를 근거에 연결한다. 안내를 짧게 하느라 예외와 핵심 조건을 없애지 않는다.
- PDF 표·알고리즘·이미지에 의존할 때는 해당 페이지를 렌더링하여 확인한다. 이미지 대체 텍스트만으로 신체 위치·손 모양·패드 위치 검수를 완료했다고 하지 않는다.
- 웹 확인일은 `sourceCheckedAt`, 의료 전문가 검토일은 별도 값으로 둔다. 실제 검토자가 없으면 null/PENDING으로 유지한다.
- 이 문서는 처치 본문을 배포 승인하지 않는다. 최종 원고와 도해의 의료 검토는 공개 전 승인 조건이다.
- 권리·최신성 미확정 항목이 있더라도 공통 화면·오프라인 구조·안전한 라우팅·테스트 개발까지 중단할 필요는 없다. 미확정 본문을 채택한 것처럼 처리하지 않는다.

## 5. 화면 구성과 사용자 흐름

### 5.1 응급상황 대처요령

`랜딩 → 응급상황 대처요령 → 주제 선택 → 짧은 안내`

- 신고·위치 설명·도착 전 준비를 구분한 카드 또는 섹션을 사용한다.
- 상단에 기존 119 전화 연결 진입점을 둔다. 독립적인 신고 프로세스는 만들지 않는다.
- 내용을 다 읽었는지, 체크를 완료했는지에 따라 119 버튼을 잠그지 않는다.
- 신고할 위치·질환·복용약을 입력·저장하는 별도 폼은 만들지 않는다. 119에 전송 완료되었다는 표시도 금지한다.
- 사용자 건강정보를 자동 불러와 안내 문장을 개인화하지 않는다.

### 5.2 응급처치 가이드 목록

`랜딩 → 응급처치 가이드 → 성인 CPR / 성인 AED / 외부 출혈 / 열화상`

- 일반 회원 카드 스타일, Noto Sans KR, 기존 Light/Dark 토큰을 재사용한다.
- 항목명과 적용 대상은 첫 목록부터 표시한다.
- 4개 항목에서는 AI 검색·문진·위험 점수·완료 배지 없이 큰 항목 카드로 충분하다.
- 지원되지 않는 상황을 ‘문제없음’, ‘다른 처치 불필요’로 판정하지 않는다.
- 심폐소생술 시작·연령 적용 조건은 회원 정보에서 추론하지 않는다.

### 5.3 상세

추천 순서:

1. 제목과 적용 대상
2. 짧은 공통 안내 및 119 전화 연결 진입
3. 이 안내의 적용 조건과 필요한 우선 행동
4. 단계별 읽기 쉬운 본문
5. 주의/금지 사항과 전환·종료 조건
6. 출처·원본 버전·확인일·권리 정보

- 전체 핵심 단계를 한 페이지에서 스크롤로 읽게 한다. 반드시 ‘다음’을 여러 번 눌러야 생명과 관련된 핵심 조치를 읽는 구조는 피한다.
- 순서·조건이 있는 안내는 번호·소제목·글자로 표현한다. 색만으로 전달하지 않는다.
- 긴 면책문이나 동의 모달을 119 또는 본문 앞에 띄우지 않는다.
- 상세 링크는 보조 기능이다. 앱 번들의 본문을 읽기 위해 WebView·PDF viewer·YouTube를 강제하지 않는다.
- 원문 링크는 사용자 탭에 의해서만 https allowlist 대상으로 연다. 연락처 링크나 임의 스킴을 콘텐츠 JSON에서 실행하지 않는다.
- 외부 링크의 오프라인 실패는 안내하고, 열려 있는 로컬 본문은 유지한다.
- 출처를 붙였다는 이유로 ‘소방청 인증’, ‘의료진 검증 완료’ 배지를 자동 생성하지 않는다.

### 5.4 그림 정책

- 초기는 읽기 쉬운 텍스트 중심으로 만들고, 필요한 동작 그림만 권리·정확성 확인 후 추가한다.
- 의료 시술·처치 자세를 ImageGen으로 생성해 별도 검수 없이 안내 그림으로 사용하지 않는다.
- 공식 카드뉴스를 화면 전체 배경으로 깔지 않는다. 허락된 그림을 사용할 경우 작은 화면·확대·대체 설명을 고려한다.
- 일반 길찾기/문서 아이콘 같은 비의료적 장식은 기존 앱 자산을 재사용한다.

## 6. 기술 구현: 작은 번들 기반 모듈

### 6.1 구성 제안

```
apps/mobile/lib/features/emergency_guides/
  domain/guide_article.dart

  data/asset_guide_repository.dart
  presentation/emergency_actions_page.dart
  presentation/first_aid_index_page.dart
  presentation/guide_detail_page.dart
  presentation/widgets/...

apps/mobile/assets/guides/ko/
  catalog.json
  articles/...
  images/...

docs/content/emergency-guides/
  source-register.md
  content-matrix.md
  drafts/...
  decisions.md

docs/qa/emergency-guides-v1-<실제 검수일>/
  README.md
  commands.md

```

위 경로의 검수일은 실제 실행일로 바꾼다. 기존에 같은 역할의 모듈이 있으면 그것을 우선 사용하고 화면을 중복 구현하지 않는다.

### 6.2 최소 데이터

- Article: id, title, category, audience, applicability, sections, warnings, relatedArticleIds, sourceRefs, contentVersion.
- Source: sourceId, publisher, title, url, publishedAt(없으면 null), sourceVersion, locator(페이지/절/그림), sourceCheckedAt.
- Review: evidenceStatus, medicalReviewStatus, rightsStatus, approvedContentHash, sourceVersionRefs.
- Public display: 사용자용 출처와 원문 버전·확인일. 실제 의료 검토가 없다면 그 날짜·검토자를 만들지 않는다.

복잡한 CMS·관리자 편집 화면·원격 배포 서버·신규 DB/API를 만들지 않는다. 소규모 파일과 리뷰 기록으로 시작한다. 콘텐츠 파일에 개인 userId, 휴대폰 번호, 건강정보, 검색 좌표, 토큰을 넣지 않는다.

콘텐츠 버전과 검토 정보는 UI 데이터 조회 시각으로 새로 찍지 않는다. 앱 실행 때마다 ‘오늘 검토됨’으로 바뀌면 안 된다.

### 6.3 승인·패키징

- 근거 비교를 마친 개발 검토본과 실제 공개 배포 가능 본문을 구분한다.
- 권리 불명/복제 금지 자료는 개발 번들에도 원문·그림을 무단 수록하지 않는다. 출처 링크·검토 기록만 보관하거나 허용된 중립적 UI fixture를 사용한다.
- 전문가 검토 전 개발 원고는 ‘검토용’으로 명시하며 공개 production 콘텐츠로 자동 승격하지 않는다.
- 공개 번들에는 배포 승인된 본문만 포함한다. 단지 UI에서 숨기고 APK 자산에 그대로 넣는 것으로 끝내지 않는다.
- 승인은 확인된 본문 해시에 연결한다. 원문·수치·그림이 바뀌면 검토 상태를 재확인한다.
- 모든 후보가 검토 중이라면 ‘가이드 전체 완료’로 보고하지 않는다. 사용 가능한 항목, 보류 항목, 남은 권리/의료 확인을 분리한다.
- 유효한 한 항목의 문제로 다른 모든 가이드나 119 접근이 종료되지 않게 한다.

### 6.4 오프라인과 독립성

- 번들 목록·본문·필요 자산은 처음부터 포함한다. 서버 다운로드 성공이나 로그인 캐시에 의존하지 않는다.
- 공개 가이드 route는 AuthGate, 건강정보 동의 gate, 세션 refresh 완료, 병원 Master readiness를 기다리지 않는다.
- 기존 회원 보호 화면에서 나와도 공개 가이드를 볼 수 있어야 하며, 이를 위해 건강정보 보호를 전체 비활성화하지 않는다.
- 가이드 읽기·탐색 자체로 NMC/MFDS/HIRA 요청을 생성하지 않는다.
- 조회이력·검색어를 회원 건강정보나 분석 이벤트에 새로 저장하지 않는다.
- 로컬 JSON은 허용된 스키마·본문 블록만 해석한다. raw HTML·script·명령·임의 딥링크 실행을 허용하지 않는다.
- 특정 파일 오류에는 해당 문서 오류와 재시도/목록 복귀를 표시한다. 빈 문서를 정상 가이드라고 표시하지 않는다.
- 검토 주기가 지났다고 읽던 응급안내를 도중에 자동 지우는 기능은 추가하지 않는다. 콘텐츠 검토/업데이트는 버전 관리된 배포 정책으로 한다.

## 7. 119 안전 경계 — 반드시 기존 구현 재사용

- 119 버튼은 로그인·연령·권한·서버 상태·원문 링크 연결 성공과 독립적이다.
- 개발·preview·자동화·수동 QA에서는 실제 전화 launcher, ACTION_DIAL, tel:119, 문자·PASS를 실행하지 않는다. OS 전화 화면을 여는 것까지 포함해 Mock에서 검증한다.
- 테스트 통과를 위해 전화 보호 설정을 잠깐 해제하지 않는다.
- 실제 배포의 기존 확인·handoff 정책은 재설계하지 않는다. Android/iOS 안내 문구를 실제로 가능한 동작 이상으로 단정하지 않는다.
- 오프라인 읽기 성공은 오프라인 상태에서 119 통화까지 보장한다는 의미가 아니다.
- 신고 전 약관·독서 확인·면책 동의를 강제하지 않는다.
- 앱이 통화 연결 성공·구급 접수·의료정보 전송을 확인한 것처럼 표시하지 않는다.
- 개인 의료정보 자동 전송·공유·QR·보호자 자동 연락 기능은 이번에 구현하지 않는다.

## 8. 실행 순서

### A. 출처/원고 검토와 짧은 Plan

1. 현재 코드·라우터·전화 안전 경계·실행 설정을 확인한다.
2. 위 S01~S11을 열어 최신 상태·버전·이용조건을 확인한다.
3. 7개 후보에 대해 원문 위치, 적용 대상, 앱 원고, 생략하지 않을 조건, 권리 상태, 최신 지침과 차이를 표로 만든다.
4. 근거·권리상 즉시 사용할 항목과 보류할 항목을 분리한다. 권리가 미확정인 자료의 허락을 사용자 승인으로 대신하지 않는다.
5. 짧은 구현 Plan과 대표 원고/상세 화면의 구조를 제시한다. 이번 승인은 곧바로 의료 콘텐츠 공개 승인이라는 의미가 아니다.

### B. 구현과 일반 앱 연결

Plan 확인 후 기존 스타일의 실제 Flutter 위젯과 Asset Repository를 구현한다. 단순한 새 Preview 앱 제작으로 끝내지 않고 최종 일반 dev 앱의 두 랜딩 진입점을 연결한다. 개발 검토본과 production 공개 가능 항목은 명확히 구분한다.

독립적인 콘텐츠 검토가 필요하면 공통 UI·번들 파서·전화 Mock·권한 없는 공개 route·실패 테스트는 병행한다. 최신성·권리 미확정 내용을 임의로 정답으로 만들어 진행하지 않는다.

### C. 최종 설치 검수

기존 설정 주입 경로로 최종 일반 APK를 업데이트 설치하고, 두 가이드와 기존 공개/회원 기능을 검수한다. 검증은 사용자 설치본을 삭제하지 않는 방식으로 수행한다.

## 11. 공개 전 보류 항목의 처리

이번에 의료 전문가 또는 권리 담당자 확인이 필요하다고 판정된 항목은 누구에게 무엇을 확인할지 구체적으로 남긴다. 막연한 ‘확인 필요’ 한 줄로 끝내지 않는다.

문의 문안 예시:

> ERoute 모바일 앱에서 해당 교육자료를 출처와 함께 한국어 안내로 제공하려 합니다. 앱은 향후 상업적 이용 가능성이 있으며, 오프라인 열람을 위한 번들 포함과 가독성을 위한 문장/레이아웃 재구성이 필요합니다. 재사용 가능한 텍스트·그림의 범위, 변경 및 상업적 이용 조건, 필요한 출처 표기와 최신판 안내를 부탁드립니다.

문의는 사용자 승인 없이 외부로 자동 발송하지 않는다. 전문가 검토·기관 허가를 실제로 받지 않았다면 받았다고 기록하지 않는다.
