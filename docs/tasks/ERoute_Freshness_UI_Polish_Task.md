# ERoute 병상정보 최신성 표시 점검 + UI 마감

## 1. 목표와 범위

완료된 회원 가입·로그인·건강정보 연동과 승인된 UI 구조는 유지한다.
이번 작업은 다음 두 가지로 한정한다.

1. 병상정보의 제공 여부와 최신성이 사용자 화면에서 혼동되는지 실제 저장 근거로 점검·수정한다.
2. 병원 상세의 중복 전화번호를 제거하고, 확인된 작은 UI 문제를 마감한다.

이 문서는 실행 지시이며, 소스코드 조사·수정 또는 재검증이 이미 완료됐다는 보고서가 아니다.
현재 저장소와 실행환경을 조사하고 변경 범위를 짧게 정리한 뒤 구현·검증한다. 대규모 아키텍처 개편이나 새 기능은 추가하지 않는다.

## 2. 사용자 확정 사항 — 중복 전화번호 제거

병원 상세의 다음 구조를 수정한다.

현재:
- 전화하기 / 길찾기 버튼
- 버튼 바로 아래에 단독으로 출력되는 병원 전화번호
- 전화 동작 안내
- 기본 정보 표의 대표전화 / 추가 전화번호

변경:
- 전화하기 / 길찾기 버튼 유지
- 버튼 바로 아래의 독립된 전화번호 텍스트만 제거
- 텍스트 제거로 남는 빈 레이아웃·불필요한 간격 정리
- 기본 정보 표의 대표전화 / 추가 전화번호 유지
- 전화 버튼의 번호 선택·유효성 검사·접근성 의미·사용자 확인·launcher 경계 유지
- 번호가 없는 경우의 비활성 상태와 필요한 설명 유지
- 전화 동작 안내 문구는 이번 중복 제거의 대상이 아니다. 실제 플랫폼 동작과 다른 문구가 발견되면 별도 보고한다.

전화번호 데이터 자체를 DTO·API·DB에서 삭제하지 않는다. 버튼 주변에서 번호를 숨기는 것을 전체 전화 기능 제거로 구현하지 않는다.
특정 병원·전화번호를 조건으로 수정하지 않는다. 동일 상세 컴포넌트를 사용하는 모든 병원에 적용한다.

## 3. 병상 최신성 — 먼저 근거 확인

사용자가 공유한 캡처에는 ‘ERoute 조회 2026.09.15 16:28’과 ‘제공기관 입력 2026.09.15 12:58 · 시간대 미확인’이 함께 보이며 배지는 ‘실시간 정보 제공’이다.
이는 당시 화면의 관찰값이다. 현재 병상 현황이나 특정 지연 원인의 증거로 사용하지 않는다.
원천 시간대가 확인되지 않았으므로 두 문자열만으로 정확한 경과시간을 단정하지 않는다.

실제 코드 필드명을 먼저 확인하여 다음 경로를 추적한다.

NMC 원문 → 수집 기록 → 현재 observation/snapshot → 검색·상세 응답 → Flutter 공통 표시

대조할 항목:
- 제공기관 입력시각 원문과 파싱 결과, 시간대 검증 상태
- 해당 snapshot을 실제 외부 응답에서 수집한 시각
- 마지막 외부 호출 시도 시각과 호출·실패·보류 결과
- 캐시 조회·상세 API 응답 생성시각
- coverageStatus, refreshStatus, 수집 신선도, 원천 신선도 및 사유
- 지도 목록과 병원 상세에서 각각 사용하는 snapshot 및 표시 규칙

우선 기존 DB·provider_response·안전한 기록을 읽는다. 필요한 최소 실측만 기존 호출 가드를 통해 수행한다. 키·전체 인증 URL·사용자 좌표·회원 건강정보를 로그나 보고서에 출력하지 않는다.

점검 질문:
1. ‘ERoute 조회’가 실제 원천 수집시각인가, 단순 DB 조회/응답 생성시각인가?
2. 캐시를 읽을 때 실제 원천 수집시각이나 제공기관 입력시각을 현재시각으로 바꾸는가?
3. 동일 원천 timestamp를 다시 수집했을 때 수집 시각만 새로워졌다는 사실을 구분하는가?
4. LIVE_AVAILABLE을 원천 데이터가 최신이라는 근거로 잘못 사용하는가?
5. 시간대·파싱 미확인 상태가 FRESH 또는 ‘최신’으로 오인되게 표시되는가?

## 4. 표시·정규화 규칙

기존 상태 축과 원문 보존 구조를 재사용한다. API에 필요한 상태가 이미 있으면 표시 계층부터 최소 수정한다.

- LIVE_AVAILABLE은 해당 원천 응답에 병원 행이 있다는 의미이며, 환자 수용 확정이나 원천 최신성 보장이 아니다.
- 원천 시간대 미확인은 UNKNOWN으로 보존한다. 임의로 한국 시간·UTC를 대입하거나 자동으로 STALE로 확정하지 않는다.
- API 제공 여부, 원천 최신성, 수집 성공 여부를 따로 해석하고 상태 문구가 근거보다 강한 주장을 하지 않게 한다.
- 원천 신선도가 미확인인 경우 예: ‘병상정보 제공’ + ‘원천 갱신시각 확인 필요’.
- 검증된 원천 시각이 기존 지연 기준을 초과하거나 기존 오류·캐시 만료 조건에 해당하면, 기존 정책에 따라 ‘이전 정보’와 사유를 표시한다.
- 새로운 지연 기준을 근거 없이 만들거나 기존 TTL·한도·초당 제한을 완화하지 않는다.
- 수집시각 표기는 의미가 확인된 필드에 맞춰 ‘ERoute 수집’ 또는 이에 준하는 정확한 명칭으로 정리한다.
- 응답 생성시각이 필요하면 원천 수집시각과 별도 명칭으로 구분한다.
- 제공기관 시각은 읽기 쉬운 형식으로 표시하되, 미확인 시간대를 숨기거나 상대시간으로 계산하지 않는다.
- 정상 행 미반환, 실제 요청 실패, 미호출·예산 보류, 실제 0을 구분한다.
- 정상 누락 확인 후 과거 숫자를 현재 병상으로 되살리지 않는다.
- HVS01 ‘일반 기준값’의 의미를 바꾸거나 점유율·수용 가능 여부를 추론하지 않는다.
- 공통 컴포넌트로 검색 목록과 상세의 표시 규칙을 일치시킨다. 서로 다른 snapshot이라면 시각·출처를 먼저 비교하며 숫자 자체를 억지로 맞추지 않는다.

문구만 바꿔 실제 시각 데이터 오류를 덮지 않는다. 필요한 계약 변경은 원인에 직접 필요한 최소 추가로 한정하고 문서·테스트를 함께 갱신한다. DB 재설계·데이터 전체 초기화가 필요하다고 판단되면 실행하지 말고 근거를 먼저 보고한다.

## 5. 작은 UI 마감

승인한 화면 구조·카드·색상은 유지한다.

- 랜딩의 ‘응급상황 대처요령’, ‘가까운 병원 찾기’는 의미 단위 줄바꿈을 우선한다. 줄바꿈 해결을 위해 글자 크기를 일괄 축소하지 않는다.
- 밝은 배경의 상태바 아이콘 대비를 점검하고 화면·테마 전환 시 올바르게 복원한다. Android 설정으로 iOS의 정상 동작까지 검증됐다고 보고하지 않는다.
- 로그인 ‘공백과 유니코드 사용 가능’은 ‘한글과 공백을 사용할 수 있어요’처럼 사용자용 문구로 정리한다. 실제 입력 허용·보안 정책은 바꾸지 않는다.
- ‘정책 미확정’ 같은 내부 표현은 ‘현재 번호 변경과 비밀번호 찾기는 지원하지 않습니다’로 정리하되 미지원 사실을 숨기지 않는다.
- 건강정보 동의 진입은 ‘동의 내용 확인하고 시작하기’ 등으로 목적을 명확히 한다. 서버 동의 저장 확인 후 기존 내부 목적 화면 복귀를 유지한다. 법적 동의 본문·버전을 임의로 개정하지 않는다.
- 알레르기·기저질환·메모만 지우는 ‘응급정보 삭제’는 ‘응급 기록 삭제’로 통일하고, 복용약·계정·동의가 유지된다는 설명을 유지한다. 전체 철회와 혼동하지 않게 한다.
- 지도에서 이전 자료라는 안내는 병원 기본 목록의 상태인지 병상정보의 상태인지 구분한다. 하나의 오래됨 상태로 모두 합치지 않는다.

위 범위 외 UX 아이디어는 후속 항목으로 기록만 한다. 번호 변경·비밀번호 복구·가이드·아이콘 등 신규 기능을 이 작업에서 만들지 않는다.

## 6. 테스트와 완료 기준

### 전화번호 UI
- 상세 버튼 주변의 독립된 번호 텍스트가 없어지고 기본 정보의 전화번호는 유지된다.
- 대표전화/추가전화가 같거나 다르거나 없을 때도 정상 렌더링한다.
- 전화 버튼 활성 조건과 기존 안전한 handoff 경계가 유지된다.
- 전화 기능 동작 검사는 fake/mock으로만 수행하며 OS/native 전화 launcher는 0회다.
- 작은 화면·큰 글씨에서 번호 제거 후 빈 공간·잘림이 생기지 않는다.

### 데이터 시각·상태
- 최근 수집 + 검증된 오래된 원천 시각.
- 최근 수집 + 시간대 미확인, 원천 시각 누락·파싱 실패.
- 같은 원천 timestamp를 다시 받음, 캐시 hit, 상세 반복 조회.
- API 실패 + 이전 snapshot, 정상 행 없음, 보류 + snapshot 없음, 실제 0.
- 시간이 경과했을 때 신선도 상태를 적절히 재평가하며 캐시 read로 원천시각이 젊어지지 않음.
- 특정 병원 전용 로직 없이 동일 입력에 동일 정책 적용.
- 상세 반복 조회·회원 동작 때문에 새로운 NMC 요청을 만들지 않음.

### 일반 앱 회귀
- 기존 Backend·Flutter 테스트, analyze, 필요한 위젯·상태 테스트 실행.
- 기존 지도 Client ID·Backend 주소·키·DB 설정과 일반 앱 실행 스크립트 재사용.
- 최종 standalone 일반 앱 com.eroute.eroute_mobile에서 비회원 지도·병원 상세와 회원 진입·세션 상태 확인.
- 회원 QA가 필요하면 가상 건강정보만 사용하며 보안 화면 보호를 해제하지 않는다.
- 실제 PASS·SMS·약품 API·전화 launcher 실행 금지.
- 외부 실측 호출은 기존 guard에서 최소 횟수로 집계하고 테스트 fixture와 구분.
- 기존 병원 Master·회원 데이터·키·원장을 초기화하지 않는다.

## 7. 보고와 다음 단계

보고서에는 다음을 남긴다.
- timestamp 문제의 실제 원인 또는 정상 동작으로 확인된 근거
- Backend/DB/REST/Flutter에서 확인한 시각 필드 의미와 변경 전후 문구
- 중복 전화번호 제거 전후 화면과 기본 정보 번호 유지 여부
- 변경 파일·실행 테스트·외부 호출량·미검증 항목
- 실제 설치 APK ID·버전·빌드 시각·SHA-256과 사용한 Backend 식별정보
- 새로 시작하거나 변경한 프로세스·포트·현재 상태·종료 방법(비밀 제외)
