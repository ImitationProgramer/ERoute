# ERoute 다음 작업 — 회원 UI 마감 및 복용약 검색 Preview

## 이번 목표

승인한 회원 UI의 디자인을 유지하면서 상태·삭제 문구를 마감하고, 복용약 검색 → 제품 선택 → 확인 → 등록의 전체 흐름을 전용 UI Preview에서 검수한다.

작업 순서는 다음과 같다.

1. 이번 작업: 회원 UI 마감 + 복용약 검색·선택 Preview.
2. 다음 작업: 휴대폰 번호·비밀번호 인증 Backend 및 승인 UI의 실제 건강정보 API 연결.
3. 후속 작업: 브랜드 아이콘과 시스템 테마 연동.

식약처 API 실제 연동은 Preview 구현 완료와 구분한다. 아이콘 작업의 선행조건으로 낱알식별·DUR까지 구현할 필요는 없다.

---

## Codex에 전달할 구현 요청

ERoute의 다음 작업으로 ‘회원 UI 마감 + 복용약 검색·제품 선택 Preview’를 수행하라.
현재 코드와 관련 문서를 먼저 확인하고, 이미 완성된 흐름은 재사용한다. 조사 결과를 짧게 정리한 뒤 아래 범위만 구현·검증하라. 새 대형 설계나 전체 UI 재디자인은 하지 않는다.

### 1. 현재 상태 확인

다음 문서와 실제 코드를 비교한다.

- docs/ui/member-ui-preview.md
- docs/qa/member-ui-preview-2026-09-15/README.md
- docs/ui/references/eroute-member-ui-v1.png
- 실제 AGENTS.md, DESIGN.md, UX-CONTRACT.md
- features/member_ui, lib/preview, MemberUiRepository 및 HealthDraft 관련 구현

문서가 이전 수동 등록 단계에 머물러 있을 수 있으므로, 검색·제품 선택 화면이 실제 코드에 이미 있는지 먼저 확인한다. 있으면 새로 만들지 않고 부족한 상태와 검증만 보완한다.

### 2. 디자인·문구 마감

- 사용자가 승인한 파스텔 항목색, 카드형 요약, 내 정보의 계정 카드와 바로가기 구성을 유지한다.
- ‘없음 · 직접 입력’은 ‘없음 · 직접 확인’으로 정리한다. 실명 또는 전화번호 본인확인을 뜻하는 표현을 사용하지 않는다.
- ‘아직 입력하지 않을게요’는 ‘아직 입력 안 함’ 등 짧은 표현으로 정리한다.
- 알레르기·기저질환·복용약의 UNSET/NONE/RECORDED 의미는 유지한다. 삭제·빈 값에서 NONE을 추론하지 않는다.
- 응급 메모는 선택 문자열로 유지하며 명시적 없음 상태를 새로 만들지 않는다.
- 응급 기록 삭제: 알레르기·기저질환·응급 메모만 삭제하고 복용약·건강정보 동의·계정은 유지한다는 범위를 안내한다.
- 건강정보 동의 철회 및 전체 삭제: 복용약을 포함한 건강정보를 삭제하되 계정·세션은 유지한다는 범위를 안내한다.
- 동의 철회는 접근하기 쉽게 유지한다. 서비스 데이터 삭제와 백업 파기 상태는 구분한다.
- ‘본인이 입력한 정보이며 현재 자동 전송되지 않습니다’는 유지한다.
- 화면을 채우기 위해 기능·문구를 늘리거나, 시안에 맞추기 위해 글자를 일괄 축소하지 않는다.
- 실제 논리 화면 너비와 글자 배율로 가독성을 검수한다. 작은 캡처 이미지의 픽셀 크기를 실제 글자 크기와 혼동하지 않는다.

### 3. 복용약 기본 등록 흐름

다음 흐름을 연결한다.

내 복용약 목록
→ 복용약 추가
→ 약 이름 검색
→ 검색 결과에서 제품 선택
→ 제품정보 확인
→ 선택적 복용 메모
→ 명시적인 등록
→ 목록으로 복귀

검색 결과가 없거나 검색이 실패한 경우에는 ‘찾는 약이 없나요? 직접 입력하기’를 보조 경로로 제공한다. 검색 결과 0건과 요청 실패는 서로 다른 상태로 표시한다.

이번에는 Preview 전용 가상 제품 Repository만 사용한다. 실제 식약처·약학정보원·NMC·ERoute Backend를 호출하거나 DB를 변경하지 않는다.

### 4. 제품과 사용자 기록 구분

- 제품 확인 화면은 제공되는 가상 필드에 한해 제품명, 함량, 제형, 업체를 구별해 표시한다.
- 실제 식약처에서 모든 필드가 제공된다고 가정하지 않는다. 실제 API의 식별자·필드 매핑은 후속 실측에서 확정한다.
- 가상 제품 ID는 명백한 PREVIEW 전용 namespace를 사용한다. 실제 품목기준코드를 만들어 넣거나 가상 값을 운영 식약처 코드로 저장하지 않는다.
- 가상 약품은 이름부터 테스트 제품임을 알 수 있게 한다. 실제 약처럼 보이는 효능·주의사항·이미지는 생성하지 않는다.
- 이미지는 없으면 일반 제품 아이콘을 사용한다. 특정 제품의 실제 사진처럼 표현하지 않는다.
- 제품을 선택했다고 사용자가 복용하는 것으로 자동 등록하지 않는다. 확인 화면에서 등록을 눌러야 목록이 바뀐다.
- 제품정보와 사용자가 직접 작성한 복용 메모는 화면과 상태 모델에서 분리한다.
- 일반적인 사용법을 개인 처방량으로 자동 채우거나 용량·횟수·안전성을 추천하지 않는다.
- 제품의 부가 설명이 없어도 제품 식별이 가능한 시나리오에서는 ‘설명 미제공’을 표시하고 등록은 가능하게 한다.
- 기존 수동 기록은 유지한다. 이름만으로 제품을 자동 연결하거나 교체하지 않는다.
- 직접 입력 기록과 제품을 선택한 기록을 구분한다. Preview 제품에는 실제 식약처 조회 완료·처방 확인 배지를 붙이지 않는다.
- 약을 추가하면 명시적인 저장 성공 이후 RECORDED가 된다. 취소·실패로 기존 목록이나 상태가 변경되지 않는다. 마지막 약 삭제 후에는 UNSET을 유지한다.

### 5. 필수 Preview 시나리오

- 최초 검색 전 / 검색 중 / 정상 결과 / 결과 없음 / 검색 실패·재시도.
- 비슷한 이름에 함량 또는 제형이 다른 가상 제품.
- 긴 제품명, 이미지 없음, 부가 설명 없음.
- 빠른 검색어 변경 시 오래된 응답이 새 결과를 덮어쓰지 않음.
- 제품 선택 후 취소, 직접 입력으로 전환, 등록 성공·실패·중복 제출.
- 기존 수동 약 편집과 삭제.
- 동의 필요, 버전 충돌, 계정 전환, 동의 철회 도중의 늦은 저장 응답.

### 6. 격리와 기존 보호 유지

- 가상 데이터와 성공 동작은 전용 Preview 진입점에서만 주입한다. 실제 서비스 위젯에 가짜 성공 분기를 추가하지 않는다.
- 일반 앱과 Preview는 같은 재사용 위젯을 사용할 수 있게 하되, 이번에는 일반 앱 라우팅과 실제 인증 경로를 교체하지 않는다.
- 기존 화면 보호, 메모리 초안 10분 수명, userId/sessionGeneration/consentEpoch/baseVersion 검사와 늦은 응답 폐기를 유지한다.
- 항목별 저장은 편집한 항목만 바꾸고 나머지 정보를 보존한다. 충돌을 최신값 덮어쓰기나 자동 재제출로 해결하지 않는다.
- Preview의 캡처 허용이 일반 앱의 민감 화면 보호를 약화시키지 않게 한다.
- Preview에서 예상하지 못한 실제 HTTP·계정 생성·세션 발급·보안 저장소 쓰기는 차단한다.
- 실제 PASS·SMS·전화 launcher를 실행하지 않는다.
- 병원 지도·검색·NMC·Backend·DB migration은 변경하지 않는다.
- 이 작업을 위해 일반 Backend나 DB를 새로 시작·종료하지 않는다. 테스트 과정의 프로세스와 남겨둔 앱 상태는 보고한다.

### 7. 제외 범위

이번에는 다음을 구현하지 않는다.

- 휴대폰 번호·비밀번호의 실제 서버 인증과 기존 계정 이전.
- 번호 소유 확인, 번호 변경, 비밀번호 분실 복구.
- 실제 식약처 호출·전수 수집·운영 약품 캐시.
- 낱알 사진 식별, DUR, 처방이력, 복용량 추천.
- PASS, SMS, 119 실제 정보 전송.
- 앱 아이콘·런처 전환·일출/일몰 계산·위치 권한 추가.
- 신규 의료정보 항목이나 개인정보의 기기 내 영구 사본.

PASS는 향후 출시의 필수조건으로 다시 넣지 않는다. 실제 인증 단계의 확정 방향은 휴대폰 번호 + 비밀번호다.

### 8. 검증과 완료 보고

- flutter analyze, 기존 테스트, 추가된 검색·선택·등록 테스트를 수행한다.
- Preview에서만 성공한 검증과 실제 Backend 연동 검증을 혼동하지 않는다.
- 밝음/어두움, 기존 320/430/720dp 화면, 글자 배율 1/2배, 키보드·뒤로가기를 검수한다.
- 일반 dev 앱의 빌드·실행, 운영 빌드의 Preview 제외도 회귀 확인한다.
- 최종 캡처는 최소한 응급정보 메인, 약 검색, 검색 결과, 제품 확인, 등록된 목록, 직접 입력, 내 정보, 삭제 확인을 포함한다.
- 실제 실행 명령, 앱 이름·application ID, 버전·빌드 시각·APK 해시, 실행한 테스트와 미실행 검증을 기록한다.
- 완료 보고 첫머리에 ‘UI Preview 완료, 실제 인증·식약처 API 연동 미완료’를 구분해 적는다.
- 저장·등록 성공은 ‘미리보기에서 반영됨’으로 안내한다.

### 완료 기준

사용자가 전용 Preview에서 가상 제품을 검색하고, 함량·제형이 다른 후보를 구분해 선택하고, 메모와 함께 등록·편집·삭제할 수 있다.
승인된 회원 화면의 디자인과 건강정보 상태 의미를 유지하며 실제 외부 요청·의료정보 저장은 발생하지 않는다.

완료 후 UI 확인을 기다린다. 실제 인증 연동과 아이콘 작업으로 자동 확장하지 않는다.
