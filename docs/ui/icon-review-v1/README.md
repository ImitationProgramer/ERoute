## 후보와 차이
- 새 Light/Dark: 길과 지평선 구도를 같은 위치에 유지하고, 중심의 붉은 십자를 남색 **E**로 바꾸는 제안. 기존 구도를 고해상도로 새로 그렸으며 참고 칸을 확대해 자산으로 쓰지 않았다.
- Light의 새 원본을 편집 대상으로 Dark를 생성했다. 두 이미지의 E, 원, 길, 산 배치가 육안으로 일치한다. 픽셀 단위 동일 기하를 검증한 벡터 원본이라고 주장하지 않는다.
- 단색: 풍경을 없애고 흑색 원·흰 E·굽은 길만 남긴 별도 실루엣 후보. 이는 흰 배경이 합쳐진 래스터 검토용 이미지이며, Android에 바로 넣을 투명 monochrome 레이어는 아니다.
- Preview: 동일 원본 위에 안전 영역 안의 **P 배지**를 공통 CSS 레이어로 합성 표시. 단색에서도 P/배지 형태를 사용한다. 아직 플랫폼 리소스로 내보내지 않았다.
- 승인 대상은 **E 심벌 변경, Light/Dark 외형, 단색 단순화, Preview P 구분**이다. Plan 승인은 디자인 승인으로 취급하지 않는다.

## 검수 결과·한계
- 실제 참고 파일과 새 원본을 모두 열어 확인했다.
- Light/Dark의 중앙 E와 길은 48/64px 및 원형 크롭에서 식별 가능. 바깥 풍경·길 끝은 마스크로 잘리지만 중앙 E는 유지된다.
- 24px에서는 Preview P 글자가 작아 판독성이 약하다. 48px 이상에서 더 분명하다. 전체 크기 구분성 통과나 모든 런처 지원으로 보고하지 않는다.
- 단색은 단순 실루엣의 시각 검토만 완료했다. 시스템 착색, adaptive 레이어 좌표·안전 영역, iOS 외형별 처리는 승인 후 플랫폼 검수 대상이다.
- Flutter 코드·Android/iOS 리소스 변경이 없어 앱 테스트·빌드·설치를 실행하지 않았다. APK 식별정보·실제 홈 화면 캡처는 이번 단계의 결과물이 아니다.

## 2단계 경계와 보존
- 사용자 디자인 승인 후에만 승인된 공통 원본에서 플랫폼 리소스를 생성한다.
- Android: 기본 컬러 + 공식 단색 테마 아이콘. Day/Night 풍경 자동 교체를 구현·완료했다고 보고하지 않는다.
- iOS: 자산·설정 준비 / 빌드 / 시뮬레이터·실기기 검수를 구분한다. Xcode 라이선스 자동 수락·전역 개발 도구 변경·도구 업그레이드 없음.
- 일반/Preview application ID·서명·세션·건강정보·지도·Backend 설정 유지. 업데이트 설치 실패나 서명 불일치를 앱 삭제로 우회하지 않는다.
- 기존 미추적 파일 삭제·초기화, 앱/런처 데이터 초기화, 실제 PASS·SMS·전화 launcher 호출 없음.
- 가이드 2개 → 기저질환 관련 진료과 v1 → 식약처 → HIRA 순서는 후속 작업으로만 유지한다. 이번에 자동 확장하지 않는다.
- 이번 작업은 검토 폴더에만 새 파일을 생성했다. 전용 headless Chrome으로 비교 페이지를 촬영했고 해당 프로세스는 종료했다. 사용자 앱·서버·에뮬레이터는 조작하지 않았다.
